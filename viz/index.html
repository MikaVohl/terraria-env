terraria-lite · an RL field guide

Can a neural network learn to play a game it has never been told the rules of?

This is terraria-lite: a 128×96-tile world with trees, caves, ore, slimes, bats, and a crafting tree 19 recipes deep. It is a C program, compiled to WebAssembly, running in this tab.

AD walk · W jump · click a highlighted cell to mine · right-click to place · E cycle block · F attack · craft from the panel

Chop a tree (click the trunk next to you), build a workbench. Every new achievement is worth exactly +1, and there are 32.

Nothing here is a mock-up. Each step you take is one call to env_step(e, action), the same function the training cluster called 2.1 billion times for the agent you are about to meet.

Keep scrolling to hand over the controls.

the agent takes over

Same world, same state, new player.

A trained policy network now picks every action. Each tick it receives an observation, outputs a probability for each of the 83 actions, and one is sampled.

The panel shows its mind, live:

  • π(a|s): the top actions it is considering right now.
  • V(s): the critic's estimate of the discounted reward still to come. During training this included a recipe-progress bonus, so it runs higher than the achievements left.
  • entropy: how undecided it is.

Nobody told it that trees give wood or that a furnace needs stone. It learned what pays from reward alone, over about 731,000 practice episodes.

Try the checkpoint buttons above the charts: the untrained network flails, while the 2.1B-step one plays with purpose.

scale

One agent learns slowly. So we run hundreds.

Reinforcement learning is hungry. Each policy update in training used 1,024 worlds stepped in lock-step, 128 steps each: 131,072 decisions per update.

Here: 256 independent worlds, each with its own seed, each played by the same network. They are spread across N Web Workers, and each worker owns its own copy of the simulator and the policy.

When an episode ends (3,000 steps, or death), the world is reset in place with the next seed. This is tl_batch_step_autoreset, in the browser.

Switch checkpoints and watch the aggregate distribution move. The mean achievements number is computed only from episodes that finished in this tab. At watchable pace an episode takes minutes; switch to full speed to finish some.

the training run

2.1 billion steps, about two hours.

This is the real log of the run behind this policy: PPO on one AMD datacenter GPU at about 296,000 steps/s. Every 134M steps the checkpoint was scored on 128 held-out validation worlds.

The curve rises fast, then flattens near 25.7 / 32. Five achievements were never earned: the iron and gold pickaxes, the iron chainmail, the wood breastplate, and climbing back to the surface after descending deep.

That plateau is the open research question. To see why, we need to zoom in on a single decision.

the RL loop

Agent ⇄ Environment

Every step is one round trip:

  1. the environment emits an observation ot,
  2. the agent answers with an action at ~ π(·|ot),
  3. the environment advances and pays a reward rt+1.

That is the whole interface. The agent never sees the C structs, the RNG, or the map. It only sees numbers going in and one integer going out.

Next we open each of the three arrows in turn.

observation · 1/4

State is not observation.

The state is everything the simulator knows: all 12,288 tiles, lighting, every mob and chest, the RNG. That is 51,040 bytes.

The agent gets an 11×9 window around itself. Unlit cells are unknown, the same as being in the dark. This makes it a partially observable problem.

observation · 2/4

99 cells → 2,376 numbers

Each cell's tile is one-hot encoded: 24 slots (23 tile kinds plus unknown), exactly one of them set to 1. A neural network can't treat "stone = 3" as a quantity, so each kind gets its own input.

Next come 99 more numbers: the light level of each cell, from 0 to 1.

observation · 3/4

The status vector: 488 numbers

Health, tool tier, facing, fall distance, depth, time left… then the inventory: 33 item slots, each count squashed as √(n / 999) so that 1 vs 5 wood is visible, while 900 vs 999 barely is.

observation · 4/4

Then the 32 achievement bits. Reward depends on which ones are already earned, so the agent must be able to see them.

Last, 4 numbers per visible cell for creatures: slime, bat, health, and movement phase. 2,963 numbers in total. Hover the strip at the top to read any index and its value.

action

83 buttons, most of them greyed out.

Move, jump, mine or place at any of 20 cells around the body, 19 recipes, attack, eat, select a block… An action mask from the simulator marks which actions would do anything right now. Masked actions get probability exactly 0.

The policy's output is a distribution, not a choice. Bar height is π(a|s). The ring marks the action that was actually sampled. Sampling, rather than always taking the top action, is how a policy keeps exploring.

Mining and placing are scored per target cell by one shared head: the heat map around the player.

reward

+1, rarely.

The environment pays +1 the first time each of the 32 achievements happens, and −1 for dying. Most steps pay nothing.

The goal is the return: the sum of future rewards, with each one discounted by γ per step. Here γ = 0.999, so a reward 700 steps away still counts for about half.

The critic V(s) tries to predict that discounted return from the observation alone. The chart compares its prediction (coral) with what actually happened later in this episode (white).

The gap between the two, step by step, is the learning signal: the advantage.

inside the agent · forward

472,718 numbers decide each move.

The "targets" network: each of the 99 cells goes through a small shared MLP (29 → 32 → 32). All cells plus the status vector feed a global trunk (3,260 → 128 → 128, tanh).

Three heads read the trunk:

  • an actor for the 43 non-spatial actions,
  • a shared target scorer that rates mine and place at each of the 20 reach cells using its 3×3 neighbourhood,
  • a critic that outputs V(s).

Colours are the real activations for this step, computed in your browser.

backward

Which way should each weight move?

Backpropagation sends ∇ log π(at|ot), the direction that makes the sampled action more likely, back through every layer. Blue and coral show its sign at each unit.

Arriving at the input, it shows which cells mattered for this decision.

PPO

Push by the advantage, but not too far.

PPO multiplies that gradient by the advantage Ât. Positive means "better than expected, do it more"; negative means "do it less". The probability ratio is clipped to [0.8, 1.2], so one batch can't drag the policy too far from the one that collected it.

Repeat 16 minibatches × 4 epochs, collect fresh data, and do it again: 16,384 times.

inside the environment

The whole world is one struct.

Env holds every byte of state in fixed-size arrays: no pointers, no allocation, no globals. Each pixel on the right is one byte of it, read live from WebAssembly memory.

Bytes that changed on the last step flash. A typical step touches somewhere between a handful and a few hundred of its 51,040 bytes.

Because state is plain bytes, a snapshot is a single memcpy. That is how this page scrubs backwards: it restores a saved Env and replays the recorded actions.

Randomness comes from one PCG32 stream inside the struct. Same seed and same actions give the same bytes, here and on the cluster. tools/viz_parity.py checks the wasm build against the native library, bit for bit.

the plateau

25.7 out of 32, and stuck.

The trained agent reliably earns 27 of the achievements. The 5 it never earns all require planning beyond its horizon: saving 10 iron bars for a pickaxe (whose reward arrives hundreds of steps after the mining), hoarding 30 wood, or returning to the surface on purpose.

A scripted player that knows the recipes scores 31.97. More steps (16B), bigger networks, and memory did not close the gap. That makes this a good testbed.
