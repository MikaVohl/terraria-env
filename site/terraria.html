Official Terraria track

LLM agents playing the unmodified game: Terraria 1.4.4 through tModLoader, normal enemies, a fresh small world, 20 minutes of game time, screenshots in and keyboard and mouse out. Progress is read from a read-only observer mod's journal, never from what the model says. Every model plays twice per world: once in real time and once with the game frozen while the model thinks.

Leaderboards

Rows are agent setups on profile default-v2, one run per world (worlds 401 and 402 are crimson, 403 is a corruption world no earlier run had seen). Extended counts facts reached out of a 19-fact catalog that separates crafting and placing from holding items; published is the 13-checkpoint subset terrariabench.com scores, which rewards possession and so also loot from chests. Both are read from the observer journal after the run and cut at the 20-minute budget. With one to three runs per row these are signals, not rankings.

Real time: the game never pauses, so every second of model latency is a second the character stands still with enemies around.

Paused: the game process is stopped (SIGSTOP) during every model call and resumed for the actions and the screenshot, so latency costs money and wall time but no game time.

One model or a planner with a fast executor

Opus 5.5 alone is slow for real time (about 4 s per screenshot) and expensive. In the combination, Opus plans every 10 to 60 game seconds and does all menu work, while Jev 1.14 picks walk, jump, chop, dig and attack moves from a catalog about every 0.3 s. Both see the same screenshots and send the same key and mouse primitives.

How fast is real Terraria?

    
For RL, speed decides everything. We measured a headless tModLoader 1.4.4 dedicated server stepping Main.Update in a tight loop on an Intel i7-9700 (Linux), with a scripted player that walks, jumps and mines with a copper pickaxe. Each run is 30 s of steady state after a 5 s warm-up, repeated three times. One agent action is 4 game ticks.

    

    

    

    
What the measurement leaves out

    

    
Running a full client-side player on the server failed: sky, filters and player saving are not initialised on a dedicated server and threw exceptions. Combat, item pickup and cursor tool use need a headless client host, which has not been built. Episode resets would also need an in-memory world snapshot, since generating a small world takes 16 s. All of this makes the numbers above upper bounds on speed.

    
Source: experiments/tml-speed-20261107/README.md (method, raw JSONL and summary script in the same directory).
